# 分离任务讨论与目标执行

- Purpose：让用户先讨论并确认目标，再自行启动执行，避免 framing 自动转入实施。

## Goal 与交付预览

更新两个 Skills、共享约定和调用示例。Frame 交付目标说明、必要文档和可复制 Goal message 后停止；execute 在用户之后明确启动时，依据确认的目标文档执行。默认任务目录分为 `goal.md`、`README.md` 和 `work-log.md`。

## 验收与证据

- Frame 的规则、UI prompt 和当前示例均不自动执行、不自动激活 Goal；允许范围内的背景读取及获授权的交接文档准备。
- Execute 核对明确启动指令和确认的目标文档；README 引用目标，进度变化不改写目标与验收条件。
- Goal message 包含具体结果、验收证据、重要约束和文档位置；关键未知未解决时标为草稿。
- 每个 Skill 可独立安装，本地引用与共享副本检查通过；官方 validator 通过。
- 更新相关行为案例，并如实记录实际运行和未运行的验证范围。

## 范围与约束

仅修改 agent-task-skills 仓库及隔离验证副本。保留先前已发布的行为记录作为历史。不修改 PROS，不安装 Skills，不创建持久 Goal。初始实施授权来自用户“合理开始提升skill开始执行”；用户随后明确要求“commit push”，授权提交并推送本次更新。

## 资源与停止条件

无用户指定数值预算。采用本地验证，不运行真实业务实验。目标、权限或事实发生关键冲突时提出具体问题；完成上述产物和适用检查后停止。

## 背景与状态

依据 2026-10-05 对话中用户确认的流程：讨论、准备 goal.md、提供 Goal message，由用户设置 Goal 并另行启动 execute。开始时仓库 main 干净，与本地跟踪的 origin/main 一致。本说明记录本次已明确授权的 Skill 修改任务，不代表已创建宿主 Goal。
